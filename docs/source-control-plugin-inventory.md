# Source control plugin inventory and migration matrix

This document is the Stage 0 baseline for splitting source-control provider behavior from provider-neutral local Git behavior. It records the runtime coupling present at commit `d8c99bd7`, the destination of every discovered call site, and the support target for GitHub, GitLab, and the deliberately small Azure DevOps scope.

## 1. Scope and non-goals

The inventory covers:

- the 13 runtime source files under `packages/daemon/src/features/github/`;
- all 19 `/api/<removed-hosted-provider>/*` route declarations in `packages/daemon/src/api.ts` and their matching daemon-client methods;
- every export from `packages/daemon-api/src/github.ts`, plus dependent shared API modules;
- every runtime renderer file found by the review searches, all source-control i18n keys, and related tests;
- coupling outside those directories in errors, shepherd, task links, project clone, daemon-client, and desktop main.

Stage 0 changes documentation only. It does not define the TypeScript contracts, implement a provider, or change runtime behavior. During migration, old `/api/<removed-hosted-provider>/*` routes, provider-specific hosted types, the `api.github` client namespace, and provider-specific error codes are deleted in the same PR stack that updates their consumers. No old entry point remains after that stack lands.

Azure DevOps is limited to discovery, authentication, repository identity, and the basic change-request create/read/list/status path. Checks, failure logs, review threads, comments, merge operations, templates, and workspace creation from a change request are outside that target.

Tests are inventory evidence, but each test migrates with the runtime symbol it exercises rather than receiving a separate architecture destination.

## 2. Terms

- **capability**: a provider-neutral operation exposed to daemon and UI consumers, such as `changeRequests.get` or `checks.snapshot`.
- **provider plugin**: the implementation of remote identity, credentials, hosting-service APIs, and remote publication for one source-control provider.
- **LocalGitBackend**: shared implementation for local repository state and commands that do not need to identify a hosting provider.
- **probe**: provider-neutral, read-only local inspection such as `git remote get-url` or parsing `.git/config`; its result is input to provider discovery.
- **basic change-request path**: create, read, list, and status only.

Support cells use `full`, `partial (gap)`, or `out-of-scope`. They describe the target of this migration, not current implementation status.

### 3.2 HTTP contract and client

`packages/daemon/src/api.ts` declares 19 GitHub-prefixed routes. `packages/daemon-client/src/index.ts` mirrors 18 client methods because `GET /api/<removed-hosted-provider>/checks` and `GET /api/<removed-hosted-provider>/review-threads` are currently daemon-internal consumers used by shepherd rather than public client methods. The client module was absent from the initial size table and is an additional coupling surface.

The Azure column has a hard allowlist: only `provider.auth`, `discovery`, `repositoryIdentity`, and `changeRequests.create/get/list/status` may be non-`out-of-scope`. A shared local capability is not part of the Azure plugin scope merely because Azure-hosted repositories can consume it. ## 5. LocalGitBackend boundary decisions

The decision rule is whether the operation must know which hosting provider owns the remote. Read-only inspection of local remote configuration does not; it produces probe data. Publication, credentials, provider-default base selection, and every change-request API operation do.

### 5.1 Required per-call review

| Git command / call site                                               | Needs remote identity | Owner                              | Basis                                                                 |
| --------------------------------------------------------------------- | --------------------: | ---------------------------------- | --------------------------------------------------------------------- |
| `pull-request-create.ts:66` `git rev-parse --show-toplevel`           |                    no | LocalGitBackend                    | validates a local worktree                                            |
| `pull-request-create.ts:67,144,185` `git branch --show-current`       |                    no | LocalGitBackend                    | reads local HEAD state                                                |
| `pull-request-create.ts:73` `git remote get-url origin`               |                    no | LocalGitBackend probe              | reads configuration; registry identifies the provider from the result |
| `pull-request-create.ts:91,98` `git rev-parse --verify <base>`        |                    no | LocalGitBackend                    | resolves a local or remote-tracking ref already present locally       |
| `pull-request-create.ts:104` `git rev-list --count <base>..<head>`    |                    no | LocalGitBackend                    | computes local graph reachability/ahead count                         |
| `pull-request-create.ts:402` `git for-each-ref refs/remotes/origin/*` |                    no | LocalGitBackend                    | enumerates locally stored remote-tracking refs; no network call       |
| `pull-request-create.ts:450` `git log <base>..<head>`                 |                    no | LocalGitBackend                    | reads local commits for title/body prefill                            |
| `pull-request-create.ts:466` `git diff --shortstat <base>..<head>`    |                    no | LocalGitBackend                    | summarizes a local diff                                               |
| `pull-request-create.ts:149` `git push -u origin <head>`              |                   yes | provider plugin `branches.publish` | publishes through provider credentials and remote policy              |
| `pull-request.ts:586` `git status --porcelain`                        |                    no | LocalGitBackend                    | reads local dirty state                                               |

`pull-request-create.ts:82` (`gh repo view` for the default branch), its PR lookup/view/create calls, and all calls in `pull-request.ts` made through `gh` need provider identity and stay in provider plugins. They are not LocalGitBackend operations.

### 5.2 Complete boundary by operation

| Operation                                                                    | Needs remote identity | Owner                                         |
| ---------------------------------------------------------------------------- | --------------------: | --------------------------------------------- |
| status, diff, commit, branch, worktree                                       |                    no | LocalGitBackend                               |
| ahead/behind and merge-base computed from available refs                     |                    no | LocalGitBackend                               |
| `remote get-url` and `.git/config` parsing                                   |                    no | LocalGitBackend probe                         |
| repository template file discovery                                           |                    no | LocalGitBackend                               |
| clone, including credential selection                                        |                   yes | provider plugin                               |
| push / publish branch                                                        |                   yes | provider plugin                               |
| preflight orchestration and provider-default base selection                  |                   yes | provider plugin composed with LocalGitBackend |
| change-request create/read/list/status/comment/merge/review/check operations |                   yes | provider plugin                               |

## 6. Known exceptions

### Angel Engine update distribution

Reason: `desktop/src/shared/i18n/locales/en.ts` says “downloads updates from GitHub Releases”, and `desktop/src/main/updater.ts` configures the updater's GitHub release provider. These describe distribution of Angel Engine itself, not a user's project repository.

Boundary: source-control provider selection must never affect the application's update channel. These references stay owned by updater infrastructure.

### Application user-agent repository URL

Reason: `desktop/src/main/ipc/url-preview.ts` includes the Angel Engine repository URL in the HTTP user-agent as application identity.

Boundary: it is metadata for outbound preview requests and does not identify, authenticate, clone, or query a user's repository.

### GitHub Copilot runtime name

Reason: `packages/daemon-api/src/agent-catalog.ts` names the GitHub Copilot CLI agent runtime.

Boundary: agent runtime branding is independent from source-control hosting and must not be routed through the source-control provider registry.

### UI metaphor comment

Reason: `workspace-git-panels.tsx` contains “GitHub Desktop-like” only in a source comment describing layout.

Boundary: it has no runtime value, type, request, or rendered copy and therefore creates no provider dependency.

## 7. Risks and response directions

| Risk                              | Why it matters                                                                                                                                                                                                                         | Direction                                                                                                                                                                                                                               |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Shepherd check/review event model | GitHub check runs expose attempt semantics, while GitLab pipelines expose jobs and retries at different levels. Fingerprints, required-state evaluation, failure-log identity, and comment progression currently assume GitHub shapes. | Define neutral event identity, lifecycle, retry index, requiredness, and terminal-state rules before changing shepherd. Preserve provider payload only inside plugin mappers and add cross-provider fixtures for retry and rerun cases. |
| GitLab private clone credentials  | `clone.ts` relies on `gh repo clone` because plain Git lacks the CLI's stored credentials. There is no existing shared path for `glab`, credential helpers, or tokens.                                                                 | Make clone a provider capability with an explicit credential strategy; evaluate `glab`, system credential helpers, and token injection without exposing secrets in command output.                                                      |
| One-time breaking migration       | Daemon paths, daemon-client methods, shared types, query keys, UI imports, errors, and translations form one connected graph. Partial publication would leave incompatible binaries and clients.                                       | Land the contract rename, provider registry, daemon routes, client, renderer, shepherd, and error/i18n updates in one ordered PR stack; release only a closed stack.                                                                    |
| Duplicate PR implementations      | `pull-requests.ts` and `pull-request-create.ts` both create and view PRs with different result models and persistence behavior.                                                                                                        | Choose one neutral change-request service contract and make persistence/workspace orchestration a caller-side concern. Validate both current UI flows against it.                                                                       |
| Default branch ownership          | Current preflight asks `gh repo view` for the default base but then performs local ref calculations.                                                                                                                                   | Let the provider return default-branch identity and let LocalGitBackend resolve and compare the corresponding local ref.                                                                                                                |
| Error-code UI coupling            | Renderer switches directly on GitHub CLI and merge error codes.                                                                                                                                                                        | Define stable operation/category/retryability fields plus optional provider metadata, then translate by neutral category.                                                                                                               |
| Link registry ambiguity           | `parseTaskLink` chooses GitHub before Linear with hard-coded branching; future hosts and self-managed instances can overlap URL patterns.                                                                                              | Give plugins deterministic match scores and keep provider selection separate from item resolution.                                                                                                                                      |
| Azure scope creep                 | Reusing broad change-request UI/types could accidentally imply checks, discussions, merge, or failure logs.                                                                                                                            | Gate UI actions by declared capabilities and test that Azure exposes only discovery, auth, identity, and basic create/read/list/status.                                                                                                 |
